Pin a major, or pin exactly

A bare major takes the newest minor the first time it resolves, then stays there: a new 17.12 never reaches a project already pinned to 17.11. Write the full version when you need to match production.

doze.hcl · a major
module postgres "postgres" {
  version = 17
}
doze.hcl · exactly
module postgres "postgres" {
  version = "17.6"
}
doze.lock · what each lands as (a new entry under each spec)
engines:
    postgres:
        "17":
            resolved: 17.11.0
            source: mirror
            hashes:
                aarch64-apple-darwin: sha256:1214c27cec0f357fbc570bc61788fde1cc918c2bced8b54e077ec990168c77f2
        "17.6":
            resolved: 17.6.0
            source: mirror
            hashes:
                aarch64-apple-darwin: sha256:8e80925b1568cc09d8a17448368b6a5e6d935c9817474c10ed7fb5aa77780fee

Each platform adds its own hash the first time it downloads, so a teammate on Linux adds a line under the same pin. Changing the version in doze.hcl adds a new entry; nothing else moves an engine pin.
