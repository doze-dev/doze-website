S3

Functional

Buckets and objects on your disk, with multipart uploads, versioning, presigned URLs, and notifications to SQS, SNS, Lambda and EventBridge.

Point your SDK at it

# eval "$(doze-aws env)" sets the endpoint and credentials
import boto3

s3 = boto3.client("s3")
s3.put_object(Bucket="receipts", Key="orders/[order-id].txt", Body=b"2 x sourdough")

In a doze stack

In a doze stack, buckets and queues live in doze.hcl beside the services that use them; doze AWS creates them when it starts. This is Larder's:

doze.hcl
module aws "aws" {
  bucket "product-images" {}
  bucket "receipts" { versioning = true }

  queue "pick-lists" {
    dlq          = "auto"
    max_receives = 5
  }
}

Fidelity

What each group of operations does here, stated plainly. Functional means it changes and returns real state; stubbed means it answers but does nothing.

OperationsStateNotes
Buckets, objects, multipartfunctionalStored on disk under the instance's data
NotificationsfunctionalSQS, SNS, Lambda, EventBridge
Bucket policiesfunctionalEvaluated under IAM soft and enforce
[an operation group]round-trip[from the service's fidelity ledger]

Bucket URLs keep AWS's shape, region included; only the suffix changes: product-images.s3.eu-west-2.aws.larder.doze.
