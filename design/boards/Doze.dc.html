One file in your repo

Onboarding is doze up.

doze.hcl says what your app needs. Connection strings wire themselves, and doze.lock pins every engine, byte for byte, so your Postgres is your teammate's Postgres. This is a slice of Larder's.

  • One Postgres, a role and a schema per service
  • Your own domain over https, for when OAuth refuses localhost
  • Migrations that run once, before the code that needs them
  • The same file runs your tests in CI: doze run -- go test ./...
  • Postgres extensions by name, coming in postgres 0.3
Read all of Larder's doze.hcl on GitHub → 
# doze.hcl
stack = "larder"

module postgres "postgres" {
  version = 18
  role   "catalog" { password = "catalog" }
  schema "catalog" { owner = "catalog" }
}

module valkey "redis" { version = 9 }

task "migrate-catalog" {
  run    = "go run ./platform/cmd/migrate services/catalog/migrations"
  inputs = ["services/catalog/migrations/*.sql"]
}

app "catalog" {
  run   = "go run ./services/catalog"
  port  = 8002
  after = [task.migrate-catalog]
  env   = {
    DATABASE_URL = "postgres://catalog:catalog@${module.postgres.address}/postgres?sslmode=disable"
  }
}
Polyglot by default

doze runs the command you'd run.

No SDK, no base image, no plugin per language. Each team keeps its toolchain; doze gives every service a name, a port, its connection strings, and sleep.

See all three in Larder →
Gogateway, identity, catalog, orders, paymentsrun = "go run ./services/orders"
Pythonfulfilment, recommendations, with uvrun = "uv run --frozen python -m fulfilment"
TypeScriptnotifications, storefront, on bunrun = "bun run dev"
Anything elseIf it starts from your terminal, it starts from doze.hcl.run = "[the command you type today]"
Add anything

Need Kafka? doze add kafka.

The newest version, its usual port, a name, wired into your app. The same for every tool below.

doze or docker compose?

Both are good tools. Containers win at shipping. For the code you write all day, here is what changes.

Questiondozedocker compose
