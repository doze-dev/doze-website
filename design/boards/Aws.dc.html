All of AWS. None of the account.

Stop waiting on a deploy to find out if your Lambda works. Stop sharing one dev account with the whole team. doze AWS is 17 services in one Go binary, speaking the real wire protocols, so your SDK, the AWS CLI, SAM and CDK point at it unchanged. No Docker, no JVM.

The console

It opens on your own traffic.

Every call your app makes, in order, with the work each one caused nested under it, a request id you can quote, and copy as curl on each row. Real AWS cannot show you this, because it is not sitting between your code and the answer.

doze AWS · /_console
1 call was refused
The same request would fail on AWS. You found out on your laptop.

Not just the wire

Every service gets a real console.

Browse buckets, peek at queues without consuming, query tables, invoke functions and read their logs, follow a state machine, and generate the IAM policy your tests actually needed. All from one binary, with no cloud account.

17 services that talk to each other

Inside a doze stack

Buckets and queues, in the same file as the app.

In Larder, the example grocer, catalog keeps product images in S3 and fulfilment, a Python service on boto3, works through pick lists on SQS. doze AWS stays asleep until one of them calls.

See Larder → 
# doze.hcl, from Larder
module aws "aws" {
  port = 4566

  bucket "product-images" {}
  bucket "receipts" { versioning = true }

  queue "pick-lists" {
    dlq          = "auto"
    max_receives = 5
  }
}
