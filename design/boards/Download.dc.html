Coming from 0.1.1?

Update doze first, then your modules. 0.1.1 can't read a module release's oldest-doze field, so doze modules upgrade on 0.1.1 could pick a release it can't run.

$ brew upgrade doze
$ doze modules upgrade
Your doze.hcl needs the new words, and doze says which line: postgres "db" {} becomes module postgres "db" {} idle_timeout becomes sleep, and the default is 2 minutes, not 5.
No surprises

What the installer does to your machine.

Three things, all listed here, all undone by four commands. No kernel extension, no telemetry. The app asks GitHub for a newer doze only when you open Settings › About.

1
Copies Doze.app to ApplicationsThe window and the bat in your menu bar.
2
Puts doze on your PATHA link to the binary inside the app, so the CLI and the app are always the same version.
3
Asks for your password once, for .doze namesSo gateway.larder.doze reaches your gateway, and two projects can both use port 5432. On a Mac it adds two things:
  • /etc/resolver/doze, which sends the .doze zone to doze's resolver and nothing else.
  • dev.doze.netd, a small network daemon that gives each service a loopback address of its own.
On Linux: the doze-netd systemd unit and a drop-in for your DNS manager. doze AWS and doze Kafka share it: whichever you run first sets it up for all three. Skip it and everything runs on 127.0.0.1.
+
Only if you declare your own domaindoze trust makes a certificate authority for this machine. Its key stays in ~/.doze/ca, readable by you alone.

Take it all back

Run these in order. The last one deletes every engine, every module and every project's data under ~/.doze, so keep it for when you mean it.

Still on 0.1.1? It installed none of the above:

$ brew uninstall doze
$ rm -rf ~/.doze
$ doze dns-setup --uninstall  # resolver file, daemon
$ doze trust --remove         # if you used domains
$ brew uninstall --cask doze
$ rm -rf ~/.doze              # all data
Trust, but check

Verify your download.

Every release on GitHub carries checksums.txt with the sha256 of each file. Doze.app is signed with a Developer ID and notarised by Apple, so it opens without a warning.

Engines and modules that doze downloads later are signed too, and checked before they run.

How signing works → 
# in the folder you downloaded to
$ shasum -a 256 -c checksums.txt \
    --ignore-missing
Doze-0.2.0.dmg: OK
$ spctl -a -vv /Applications/Doze.app
# accepted
# source=Notarized Developer ID
# origin=Developer ID Application:
#   [team name]
Then

Your first stack in five minutes.

The first doze up downloads the engines it needs, so give it a minute. After that it starts in seconds, and works offline.

1

Install

The app above, or the CLI on its own.

$ brew install --cask \
    doze-dev/tap/doze
2

Point it at a project

doze init reads your repo and writes a doze.hcl. Or borrow Larder, a grocery service in Go, Python and TypeScript.

$ cd your-project
$ doze init
$ git clone \
    https://github.com/doze-dev/doze-examples
$ cd doze-examples/larder
3

Bring it up

Everything starts in order, then dozes when nothing is using it. For Larder, stock the shelves once.

$ doze up
$ doze task seed-catalog
