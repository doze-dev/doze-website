On 0.1.1doze 0.1.1 can't check a release's oldest doze: on a fresh project it takes the newest release regardless, which is why this page tells you. Update doze before doze modules upgrade; a doze.lock already pinned to postgres 0.2.4 keeps working until you do. 0.1.1 also has no doze add and uses the old syntax (postgres "orders" {}).

Before doze 0.2 launched, every release in the index ran on 0.1.1; the 3 Nov builds are the first stamped with an oldest doze.

What doze says when a release needs a newer doze

From 0.2, doze reads each release's oldest doze itself: it skips releases it can't run and picks the newest one that fits. Only when none fits does it stop, with one of these.
