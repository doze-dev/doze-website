Versions

Five releases resolve, newest first. Nothing is ever taken down: a project pinned to any of them keeps working, and doze modules upgrade is the only thing that moves a pin.

  1. postgres 0.2.1 – 0.2.4 any doze Jul–Nov 2026. No oldest-doze field, so they run on every doze, 0.1.0 and up.
  2. postgres 0.2.5 Current doze 0.2.0 or newer The index carries doze: 0.2.0 for it.
  3. postgres 0.3 Coming doze 0.2.0 or newer Extensions by name. Built on a branch, not released.

The release tool writes the field from the SDK the module was built with, always as three numbers. A doze older than a release's minimum skips it and takes the newest release that fits.

doze 0.1.1 can't read a release's minimum doze. Update doze first, with brew upgrade doze, then run doze modules upgrade.

Upgrading a project

A project stays on the release in its doze.lock until you move it. Check first; the upgrade takes the newest release your doze can run, verifies it, and rewrites the pin.

1. See what would move (changes nothing; exits 1 if anything would)
$ doze modules upgrade --check
ENGINE    SOURCE         PINNED  SELECTED  STATUS
postgres  doze/postgres  0.2.4   0.2.5     upgrade available

1 module upgrade(s) available — run doze modules upgrade
2. Move the pin
$ doze modules upgrade postgres
ENGINE    SOURCE         PINNED  SELECTED  STATUS
postgres  doze/postgres  0.2.4   0.2.5     upgraded

doze.lock updated — commit it so the team and CI pick up the same builds

On doze 0.1.1, update doze first: it can't read a release's minimum doze. Engine pins (postgres "17") never move with a module upgrade.
