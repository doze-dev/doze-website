What changed, and when.

Every release of doze, doze AWS and doze Kafka, and the notable module releases, newest first. Every module release is on that module's Versions tab. Upgrading doze never changes what a project runs: engines and modules stay pinned in its doze.lock until you move them.

doze 0.2 Latest [0.2 release date]

A desktop app, your own domain over https, and a stack that remembers how you left it.

New

  • The app. The Library shows every stack with a switch. Each stack in Tiles, List or Map. ⌘K reaches across every stack. A Needs you bell, and the bat in the menu bar.
  • Your own domain, over https. domains = ["dev.acme.com"] on an app, then doze trust once.
  • Take one service out of this run. doze off and doze on, or the switch on its row.
  • A failed start explains itself: what went wrong, how to fix it, and which process holds the port it wanted.
  • doze on its own opens the app. Over SSH it is still the terminal dash.
  • doze up remembers what you started and offers the same set next time.
  • doze = ">= 0.2" in doze.hcl. doze skips module releases it can't run, and says to update.
  • doze migrate postgres moves Postgres data to a new major.
  • Doze.app for the Mac, as a disk image or brew install --cask doze-dev/tap/doze.

Changed

  • Services go to sleep after 2 minutes, not 5.
  • An app with a port sleeps too; a request wakes it. sleep = "never" keeps it awake.
  • Renamed: depends_on is after, idle_timeout is sleep. The old spelling prints the new line.
  • Exit codes mean something (2 usage, 4 unknown name, 5 bad config…); --json gives one envelope everywhere.

Fixed

  • after on a module block works.
  • Two data races in the daemon.

Module releases that need doze 0.2.0

  • postgres 0.2.5, valkey 0.2.2, ferret 0.2.4, temporal 0.2.3, mariadb 0.2.2 and kvrocks 0.2.2 download their engines through doze (doze-sdk v0.10.0). An older doze skips them and keeps the release it has. In the registry

Coming with postgres 0.3

  • Postgres extensions by name: extensions = ["vector", "pg_cron"], pinned in doze.lock. See the catalog
Upgrade:
$ brew upgrade doze
Release on GitHub

Coming from 0.1.1: update doze before you run doze modules upgrade, because 0.1.1 can't tell which module releases need a newer doze. The old spellings (idle_timeout, depends_on) stop with an error that prints the new line. Full notes

FModule · ferret 0.2.3 2 Nov 2026

FerretDB starts on Linux when the data folder has a capital letter in it.

Fixed

  • The Mongo driver read the socket path as a host name and lowercased it, so on a case-sensitive filesystem start-up waited for a socket that did not exist. The module now dials the socket directly. macOS hid it: its filesystem ignores case.
Upgrade a project's pin:
$ doze modules upgrade ferret
