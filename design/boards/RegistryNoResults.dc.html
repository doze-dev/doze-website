No module, Postgres extension or bring-your-own tool is called cassandra, has it as an alias, or mentions it. That's 8 modules, 16 extensions, 9 tools and the docs searched.

Three ways forward

1

Run it yourself, today

Works today

doze runs anything with a port as a service. doze add with a name it doesn't know writes the generic block: a download to fill in.

terminal
$ doze add cassandra --port 9042
→ cassandra is not a doze module — adding it as a service
  nothing found on this machine — the block is a download to fill in
  other ways: --as installed · --as container · --as download
doze.hcl, as written: fill in download and run
service "cassandra" {
  # fetched once, pinned in doze.lock by its checksum, and run from the archive
  download = "https://example.com/cassandra-darwin-arm64.tar.gz" # fill this in
  run      = "./cassandra --port $PORT"
  port = 9042
}
  • downloadPut the real archive URL here. doze fetches it once and pins its sha256 in doze.lock; a changed file is refused.
  • runA placeholder: doze doesn't know Cassandra's flags. Change it to the real start command, in the foreground (Cassandra's is bin/cassandra -f, port set in its config).
  • portWhat doze listens on and wakes it for. $HOST, $PORT and $DATA are filled in at run time.
  • --as containerWrites run = "docker run --rm -p $HOST:$PORT:9042 cassandra" instead, if you have Docker.

doze still gives it a name, a port, sleep and wake, and logs. It isn't signed by doze. How bring-your-own works

2

Ask for a module

Say what you'd run it for and which version. A module means doze pins the engine, signs it, and declares keyspaces in doze.hcl.

doze-dev.com keeps no search log, so a missing module only gets noticed when someone asks.

3

Write one

A module is a Go plugin that speaks doze's module protocol 1. The official ones are open source to copy from: six in doze-modules, doze AWS and doze Kafka in their own repositories.

Outside publishers aren't open yet; the publish page says how it will work.
